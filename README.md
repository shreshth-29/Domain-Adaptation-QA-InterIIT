# DevRev Inter IIT PS: Domain Adaptation for Question Answering

Code from the IIT Roorkee contingent's work on the DevRev problem statement "Expert Answers in a Flash: Improving Domain-Specific QA" at Inter IIT Tech Meet 11.0 (February 2023).

The problem statement asks for a QA pipeline over a SQuAD 2.0 style dataset where every question and paragraph is tagged with a theme. Given a question, the system has to decide whether it is answerable from the paragraphs of its theme, pick the paragraph that contains the answer, and then extract the exact answer span. Questions at test time come from themes the model may not have seen, so the extractive QA model has to hold up on unseen domains. See `docs/problem_statement.md` for the full description.

This repository holds the domain adaptation experiments we ran for the extractive QA stage. Two methods from the literature were adapted to SQuAD 2.0 (including unanswerable questions) and run with BERT-base as the reader:

| Folder | Method | Paper |
|---|---|---|
| `CAQA/` | Contrastive adaptation with synthetic target-domain QA pairs generated by a T5 question generator | Yue et al., EMNLP 2021 |
| `QADA/` | Hidden-space augmentation (Dirichlet synonym sampling, attentive context cutoff) with attention-based contrastive adaptation | Yue et al., EMNLP 2022 |

Both are built on the authors' public code (see Acknowledgement). Our changes were to make the pipelines run on SQuAD 2.0 with `version_2_with_negative`, add the SQuAD 2.0 evaluation script with no-answer thresholds, add a `--debug` flag for running on a tiny subset, and write the driver scripts in each folder.

## Setup

Each folder is a separate project with its own environment, because the two upstream codebases pin different versions of torch and transformers.

```bash
cd CAQA            # or QADA
python3 -m venv CAQA_venv && source CAQA_venv/bin/activate
pip install -r requirements.txt
bash download_data.sh      # SQuAD 2.0 and MRQA into ./data
```

For CAQA, the synthetic target-domain QA pairs generated with T5-small and T5-base are needed for the adaptation run:

```bash
bash setup.sh              # downloads the shared Drive folder into ./data/synthetic
# or
bash download_syn_files.sh
```

## Running

CAQA, source only (SQuAD 2.0 train, evaluate on SQuAD 2.0 dev):

```bash
cd CAQA && bash run.sh
```

CAQA with generated target-domain data and the contrastive adaptation loss:

```bash
cd CAQA && bash qg_run.sh
```

QADA, source training followed by adaptation:

```bash
cd QADA && bash run.sh
```

`run_adaptation.sh` exposes the augmentation hyperparameters (`--dirichlet_ratio`, `--cutoff_ratio`, `--lambda_c`). They are set to 0 in the checked-in script, which reproduces the source model as a baseline; raise them to turn the augmentation and contrastive loss on. Pass `--debug True` to any entry point to run on a tiny subset.

Both `evaluation_v2.py` scripts take the dev file, the predictions file and the null-odds file, and report exact match and F1 overall, on answerable questions, on unanswerable questions, and the best scores with a tuned no-answer threshold.

## Results

`results/caqa_squadv2_dev_eval.json` is the SQuAD 2.0 dev output of one CAQA run recorded during the competition. Overall EM 26.3 and F1 31.7 at the default threshold, with HasAns F1 62.5 and best F1 52.5 after threshold tuning. The low NoAns score shows that the no-answer threshold matters a lot for this data, which is why the final pipeline treats answerability as a separate step before span extraction.
