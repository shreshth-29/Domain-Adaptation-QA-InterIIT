# DevRev Inter IIT PS: Domain Adaptation for Question Answering

Code from the IIT Roorkee contingent's work on the DevRev problem statement "Expert Answers in a Flash: Improving Domain-Specific QA" at Inter IIT Tech Meet 11.0 (February 2023).

## Problem

The problem statement asks for a QA pipeline over a SQuAD 2.0 style dataset in which every question and paragraph is tagged with a theme. Given a question, the system has to do three things:

1. Decide whether the question is answerable from the paragraphs of its theme.
2. Pick the paragraph that contains the answer.
3. Extract the exact answer span.

Questions at test time come from themes the model may not have seen, so the extractive QA model has to hold up on unseen domains. The pipeline is judged on accuracy together with latency and resource usage. See `docs/problem_statement.md` for the full description.

## Approach

This repository holds the domain adaptation experiments we ran for the extractive QA stage. Two methods from the literature were adapted to SQuAD 2.0 (including unanswerable questions) and run with BERT-base as the reader:

| Folder | Method | Paper |
|---|---|---|
| `CAQA/` | Contrastive adaptation with synthetic target-domain QA pairs generated by a T5 question generator | Yue et al., EMNLP 2021 |
| `QADA/` | Hidden-space augmentation (Dirichlet synonym sampling, attentive context cutoff) with attention-based contrastive adaptation | Yue et al., EMNLP 2022 |

Both are built on the authors' public code (see Acknowledgement). Our changes were:
- making the pipelines run on SQuAD 2.0 with `version_2_with_negative`;
- adding the SQuAD 2.0 evaluation script with no-answer thresholds;
- adding a `--debug` flag for running on a tiny subset;
- writing the driver scripts in each folder.

## Results

`results/caqa_squadv2_dev_eval.json` is the SQuAD 2.0 dev output of one CAQA run recorded during the competition (11,873 questions):

| subset | questions | exact match | F1 |
|---|---|---|---|
| all, default threshold | 11,873 | 26.3 | 31.7 |
| answerable (HasAns) | 5,928 | 51.8 | 62.5 |
| unanswerable (NoAns) | 5,945 | 1.0 | 1.0 |
| all, tuned no-answer threshold | 11,873 | 51.9 | 52.5 |

The NoAns score is very low at the default threshold, so the no-answer threshold matters a lot for this data. This is why the final pipeline treats answerability as a separate step before span extraction.

The repository has no figure of our own results. The images under `CAQA/pics/` are from the upstream CAQA paper and show its results, not ours.

## Reproduction

### Setup

Each folder is a separate project with its own environment, because the two upstream codebases pin different versions of torch and transformers.

```bash
cd CAQA            # or QADA
python3 -m venv CAQA_venv && source CAQA_venv/bin/activate
pip install -r requirements.txt
bash download_data.sh      # SQuAD 2.0 and MRQA into ./data
```

For CAQA, the adaptation run needs the synthetic target-domain QA pairs generated with T5-small and T5-base:

```bash
bash setup.sh              # downloads the shared Drive folder into ./data/synthetic
# or
bash download_syn_files.sh
```

### Running

CAQA, source only (SQuAD 2.0 train, evaluate on SQuAD 2.0 dev):

```bash
cd CAQA && bash run.sh
```

CAQA with generated target-domain data and the contrastive adaptation loss:

```bash
cd CAQA && bash qg_run.sh
```

QADA, source training followed by adaptation:

```bash
cd QADA && bash run.sh
```

`run_adaptation.sh` exposes the augmentation hyperparameters `--dirichlet_ratio`, `--cutoff_ratio` and `--lambda_c`. Pass `--debug True` to any entry point to run on a tiny subset.

Both `evaluation_v2.py` scripts take the dev file, the predictions file and the null-odds file. They report exact match and F1 overall, on answerable questions and on unanswerable questions, plus the best scores with a tuned no-answer threshold.

## Limitations

- **One recorded run.** Only one CAQA run has a recorded result in the repository. No QADA result is recorded.
- **QADA baseline settings.** In the checked-in `run_adaptation.sh` the augmentation hyperparameters are set to 0. This reproduces the source model as a baseline. Raise them to turn the augmentation and the contrastive loss on.
- **Thresholds.** At the default no-answer threshold the recorded CAQA run almost never predicts "no answer" (NoAns EM 1.0), so the overall score depends heavily on the tuned threshold.
- **Not included.** Data, model checkpoints, logs and virtual environments are ignored by git (see `.gitignore`). They have to be downloaded or produced again.
